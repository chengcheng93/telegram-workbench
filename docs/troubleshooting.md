# 常见问题

先确认你正在按[新手上手指南](getting-started.md)从源码启动。以下命令都在包含 `server.py` 的项目目录执行；不要打开真实动作反复试错。

## 提示 `python3.14: command not found`

安装或确认 Python 3.14。macOS 可按 [Python 官方安装说明](https://docs.python.org/3.14/using/mac.html)操作；安装后关闭并重新打开终端，再运行 `python3.14 --version`。

不要用系统里的旧 `python3` 随意替代，也不要修改系统 Python。当前已验证的是 macOS + Python 3.14，没有承诺其他 Python 版本兼容。

如果提示 `git: command not found`，可以直接使用 GitHub 的 **Code → Download ZIP**，无需为下载项目先配置 Git。

## 找不到 `server.py`、`requirements.txt` 或 `.venv/bin/activate`

通常是终端所在目录不对。输入 `cd` 加空格，把包含 `server.py` 的文件夹从 Finder 拖进终端，再回车；用 `ls server.py` 检查。ZIP 解压后可能多包了一层文件夹，需进入真正的项目目录。

如果目录正确而 `.venv` 仍不存在，先按上手指南创建虚拟环境。移动或重新下载项目后，旧虚拟环境的路径可能失效，需在新目录重新创建并安装依赖；不要移动正在运行的数据目录。

## `python` 或 `pip` 找不到；提示没有 `telethon` 模块

先激活项目环境，再让该环境的 Python 安装依赖：

```sh
source .venv/bin/activate
python -m pip install -r requirements.txt
```

使用 `python -m pip`，避免把依赖装到另一个 Python。不要用 `sudo pip`。若安装失败，先看终端里第一条具体错误；网络下载失败与权限不足需要分别处理。

如果 macOS 官方 Python 安装后出现证书验证错误，按 [Python 官方 macOS 说明](https://docs.python.org/3.14/using/mac.html)运行其附带的 `Install Certificates.command`；不要关闭证书校验来绕过错误。

## 报错没有 `fcntl` 模块

后台依赖 `fcntl`，Windows 原生环境当前不支持。不能通过安装一个同名依赖解决。macOS 是已验证环境；Linux 可尝试源码运行，但未完成整体验证。

## 页面没有自动打开、旧地址失效，或提示令牌缺失

后台使用随机本机端口和访问令牌。只复制终端打印的 `http://127.0.0.1:端口`，或使用旧书签，可能缺少访问令牌。

打开另一个终端，进入同一个项目目录，然后运行：

```sh
source .venv/bin/activate
export TG_WORKBENCH_STATE_DIR="$HOME/.local/share/telegram-workbench"
python server.py
```

这会重新打开相同数据目录的现有面板，或在后台已退出时重新启动。不要手动修改 `instance.json`、读取并分享令牌，或开放本机端口到公网。若系统无法调用默认浏览器，先修复本机默认浏览器设置，再重试启动入口。

双击 `.app` 或 `启动.command` 后提示“本机运行环境缺失”时，也请改用上述源码方式；这些入口依赖原开发目录环境。

## 重开后账号都不见了

先别重新登录，也别删除文件。确认：

- 进入的是原来的项目目录，激活的是其中的 `.venv`。
- 本次也执行了同样的 `export TG_WORKBENCH_STATE_DIR="$HOME/.local/share/telegram-workbench"`。
- 之前是否使用了另一个自定义数据目录。

使用不同数据目录会打开不同的本机数据。先安全退出误开的空工作台，再用原数据目录启动；不要把两套数据库或会话文件手动混在一起。

## API 凭据、验证码或两步验证无法通过

- **API ID / API Hash 错误**：到 Telegram 官方 [my.telegram.org](https://my.telegram.org/) 的 **API development tools** 核对自己的值，在本机“设置”同时填写并保存。API ID 是数字，API Hash 完整复制，不是 Bot Token。参见 [Telegram 官方获取说明](https://core.telegram.org/api/obtaining_api_id)。
- **手机号格式错误**：使用带 `+` 和国家码的完整号码。
- **没有收到验证码**：查看界面显示的实际渠道，检查 Telegram 提示的接收位置；渠道由平台决定，不保证是短信。不要连续请求。
- **验证码错误或过期**：核对最新一次验证码；过期后按页面流程重新获取。
- **要求密码**：这是账号已设置的两步验证密码，不是 API Hash 或验证码。忘记密码时按 Telegram 官方账号恢复流程处理。

不要把手机号、验证码、密码、API Hash 或会话文件发给项目作者或贴到问题报告里。

## 显示等待、限流、账号受限，或任务暂停

Telegram 给出等待时间时，按界面恢复时间等待，不能提前解除。没有时长的限制需人工检查账号状态；“解除本地暂停”不表示 Telegram 已解除限制，也不会自动恢复任务。

恢复前核对账号授权、网络、目标群权限和逐项结果。本项目不提供绕过等待、自动换号或规避平台限制的办法，也不承诺固定安全的每日添加或邀请数量。

## 邀请失败、群没有出现在列表，或不能邀请

先确认选对账号，并刷新该账号的群组和权限。账号能看见某个群，不代表有邀请权限；对象的隐私限制、既有成员状态或平台限制也会影响结果。

在任务详情中查看具体分类与原因。接口没有报错不等于对象已经入群；以“已核实加入”等证据为准。不要未经同意改发邀请链接，或换账号重复邀请。

## 显示“未核实”，是否直接点重试

先检查任务详情或消息状态，用界面的核实/恢复前检查读取实际结果。超时、断线或中断时，请求可能已经成功提交，未知不能等同于失败。

只有后台已确定失败、且允许重试的项，才使用对应的“重试确定失败项”。停止或取消不会撤销已提交请求；清空中断后需重新准备、备份并完整确认，不能靠普通重试继续删除。

## “不支持完整清空”、保存号码范围未知，或导出要求等待

这是平台能力或范围证据不足造成的保护。完整保存号码读取需要 Telegram 允许 takeout 导出，返回号码没有注册状态字段；`saved_count` 也不能直接当作未注册号码数量。

无法可靠核实完整删除范围时，最终清空会被阻止。若平台要求等待，请等待后重新准备。已注册联系人可按需使用“删除选中”的逐项预览流程，但不能把它称作完整清空。清空备份没有一键恢复。

确认前名单变化、备份不可读或摘要不符时，原确认会作废。不要修改数据库或绕过范围检查；先重新准备并核对。

## 文件权限错误、会话被占用，或数据库不可写

确认数据目录属于当前用户、位于可写的本机磁盘，而且每次使用同一个 `TG_WORKBENCH_STATE_DIR`。不要使用只读目录、共享目录，或用管理员身份运行一次后再换普通身份。

如果会话被另一个后台持有，先在对应程序中正常停止并退出，再连接。不要删除锁文件、复制正在使用的会话，或同时让旧程序和新程序操作同一个会话。

不要把数据目录权限改成所有人可写。程序的私有目录权限为 `700`、私有文件为 `600`；若数据由其他用户创建，应先停止程序并处理所有权问题，再启动。

## 页面与后台断线，或某个账号离线

两种情况分开查看：页面顶部“与本机后台连接中断”表示浏览器没有连到本机服务；账号“离线/重连中”表示该账号的 Telegram 连接状态。

先检查启动终端是否仍在运行、电脑是否唤醒及网络是否可用。页面连接问题可用同一启动命令重新打开；单个账号问题可在“账号管理”检查并重新连接。不要因断线立即删除数据或重复提交动作。恢复后先核实未知项，监听不会补抓离线期间的历史消息。

关闭浏览器不会停止后台；需要暂停时使用“暂停全部自动化”，需要退出时使用“设置 → 退出后台程序”。

## AI 按钮不可用，或没有自动回复

AI 默认关闭，需要在“设置”配置服务地址、模型及所需密钥，并在生成时明确同意当前数据范围。可用性还取决于你配置的服务。

当前 AI 只生成回复或任务草稿。你需要审阅、采用，再人工发送或确认任务；它不会自动回复或自动执行。

## 怎样提交问题

在[项目 GitHub 页面](https://github.com/chengcheng93/telegram-workbench)提交脱敏报告，可以包含：

- macOS / Linux 版本、`python3.14 --version` 结果，以及 ZIP 或 Git 下载方式。
- 出错的页面和步骤，例如“账号 A → 联系人 → 刷新”，并说明期望结果与实际结果。
- 已去除敏感内容的错误文字，发生时间，以及是否显示“等待”“未核实”或“断线”。

**不要附上凭据、访问令牌、手机号、聊天内容、联系人或客户名单、数据库、会话文件、原始备份。** 截图也要遮住姓名、号码、群名、消息、路径中的个人信息和服务密钥。用“账号 A / 账号 B”“测试群”等占位名称即可；无需为报告再次执行真实发送、添加、邀请或删除。
