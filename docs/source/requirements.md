# TG 多账号工作台 · 产品需求与界面设计

版本：V0.2 完整评审稿｜2026-10-22

本版取代 V0.1，纳入用户提供的 TG 联系人助手 v2.2.1 全部七项功能，并扩展为分账号管理。以用户提供的行为说明为功能依据；截图为等待登录状态，不能据此推断下方功能缺失。本次交付为需求与视觉设计，不包含程序实现或旧版代码审计。

## 1. 产品定位与设计假设

为个人提供一个中文电脑端工作台，集中管理本人拥有的 7～8 个 Telegram 账号。既能像聊天软件一样查看消息、手动聊天，也能用可追踪的任务管理联系人和群邀请，并通过 AI 生成回复草稿或将自然语言转换为任务。

已确认需求：多账号登录与管理、查看聊天消息、手动发送消息、添加和删除联系人、邀请联系人入群、AI 辅助执行，以及完整界面设计；继承 v2.2.1 的多群监听、新发言者自动添加、仅预览、批量邀请逐人核实、全量联系人清空前备份与二次确认、运行控制和最近动态。每个账号拥有独立监听/拉取配置及运行状态。

本稿采用的设计假设，尚待评审：单人使用；首版以本地浏览器面板运行；中文浅色界面；首批支持 8 个账号；文字与图片优先；AI 默认只生成草稿；批量任务先预览再执行。手机号、验证码、密码不交给 AI。

成功标准：8 个独立账号可被管理；当前账号和发送身份始终清楚；日常聊天不需要频繁切回官方客户端；每个任务都有明确结果；断线和重启不会造成消息或邀请重复发送。

## 2. 全局信息架构

主导航：聊天、监听、联系人、群组、任务中心、账号管理、设置。群组可作为聊天中的群聊子页，需有明确入口。联系人包含“联系人列表 / 批量邀请 / 联系人清理”三个子页。账号列表固定显示在主导航右侧，页面滚动时仍保留当前账号上下文。

顶部全局区：产品名称、在线账号数、待登录账号数、连接状态、通知、暂停全部自动化任务。暂停不影响人工发送；全局暂停的准确语义见第 15 节。

聊天页以四个主要区域组织：导航与账号选择区、聊天列表、消息内容、联系人资料与 AI 辅助区。右侧资料区可折叠，较窄窗口优先保留聊天内容。首版重点适配 1440×900 及以上桌面尺寸，1280 宽时收起辅助栏，不承诺手机完整体验。

所有操作都显示所属账号。全部账号视图下，聊天列表的每一项均带账号标识；打开会话后，发送身份锁定该会话所属账号。切换账号时保留各会话草稿。

## 3. 页面规格

### 3.1 聊天工作台

账号栏：全部账号、8 个账号头像与名称、在线状态、未读数、添加账号入口。筛选账号不改变其登录状态。

聊天列表：搜索、全部/未读/私聊/群聊筛选；头像、名称、最近消息、时间、未读数、账号标签；置顶与静音标识。首版搜索已同步的本地消息和聊天名称，完整云端搜索后续扩展。

消息区：聊天名称、所属账号、连接状态、加载更早消息、文字和图片、时间、回复引用、发送状态。编辑与撤回仅在 Telegram 当前权限和时限允许时提供。首版支持文字、图片、文件收发及回复；语音、视频等可显示附件入口，完整内置播放器后续完善。

输入区：文字输入、附件、表情、发送；Enter 发送、Shift+Enter 换行，可在设置修改。手动消息草稿不会因切换聊天丢失。上传显示进度，可取消；发送失败显示原因及重试入口。发送结果不明确时先核对状态，不盲目重试。

右侧辅助区：联系人资料、标签、备注、关联账号、最近操作、人工/AI 模式、AI 回复草稿。人工接管后，取消该聊天尚未发送的 AI 回复任务并禁止新增自动回复；恢复模式必须由用户明确操作。

聊天模式：默认人工；AI 辅助模式仅提供草稿，点击采用后放入输入框，仍由用户发送。可配置的 AI 自动回复留到第二阶段，按账号及会话白名单开启，不能由模型自行扩大适用范围。

### 3.2 账号管理与登录

表格字段：头像、内部名称、手机号脱敏、账号用户名、连接状态、未读、最后同步时间、当前任务、操作。状态包括未登录、验证中、在线、断线重连、等待平台允许、需要重新登录、受限、已停用。

添加账号采用步骤弹窗：说明并开始 → 手机号 → 验证码 → 如需要输入两步验证密码 → 连接成功 → 设置内部名称。验证码送达渠道由 Telegram 决定，界面显示实际返回状态，不承诺必定短信送达。支持取消、验证码过期、密码错误、请求过频的提示。

首版以手机号验证码流程为范围，二维码登录作为后续可选项。应用自身 API 凭据在初始设置中配置一次；每个账号保存独立会话。复用会话恢复连接，失效后要求重新授权。

账号操作：打开聊天、修改内部名称、暂停本账号任务、重新连接、退出登录、从工作台移除。退出登录需确认并撤销对应会话；移除本地数据与 Telegram 注销账号必须明确区分，本产品不提供注销 Telegram 账号功能。移除时展示受影响任务并停止这些任务。

### 3.3 联系人

按账号筛选、姓名/用户名搜索、标签筛选。字段：名称、用户名、可见手机号、所属账号、标签、备注、邀请授权记录及时间。

支持手动添加、表格导入预览、删除联系人。首版接受 CSV，模板字段为账号标识、姓名、手机号或可用用户名、标签、备注、同意邀请的记录。导入先校验格式、去重、显示无效行，不自动发送消息。不同账号中的同一个人分别保存，跨账号仅作关联展示，不混用 Telegram 访问凭据。

“添加联系人”不等于双方互加。“删除联系人”仅删除该账号通讯录中的联系人，不自动拉黑、不删除历史消息、不移出群。删除前展示具体账号、对象和数量。

### 3.4 群组

展示各账号可访问的群：群名、所属账号、类型、权限、成员数（可获取时）、最近同步时间。进入后可聊天和查看当前可获取的群信息。

邀请流程：选择群 → 选择有权限账号 → 选择已同意对象 → 检查是否已在群中及已存在任务 → 预览 → 执行。直接邀请受群权限和对方隐私设置影响；不能加入时显示原因。邀请链接是独立可选任务，不能失败后擅自向对方私信发送链接。

同意记录是本地业务依据，不代表 Telegram 必然允许添加。无权限、隐私拒绝、无法解析用户等状态不可通过更换账号自动绕过。

### 3.5 任务中心

任务类型：添加联系人、删除联系人、邀请入群、发送邀请链接、经确认的消息发送。每种类型有独立预览，首版批量消息仅用于明确选择并确认的联系人，不提供抓取群成员或向陌生人批量营销流程。

列表字段：任务名称、类型、账号、目标数量、进度、状态、创建时间、计划时间、最近结果、操作。支持搜索及按账号、类型、状态筛选。

新建任务：类型 → 账号 → 对象 → 参数 → 预览 → 确认。预览显示目标群、发送身份、具体名单、消息正文、去重结果及将改变的数据。AI 生成的任务与手动创建任务共用此流程。

任务状态：草稿、待确认、排队、运行、暂停、等待平台允许、部分成功、成功、失败、取消。每个对象单独记录结果；父任务部分失败时不能显示全部成功。

控制：暂停阻止后续步骤，已提交请求可能仍会完成；取消仅取消未执行项；重试只针对确定失败且允许重试的项；完成记录不可冒充可撤销操作。删除联系人、发送消息及群邀请不能承诺一键恢复。

每个账号有独立执行队列，交互发送优先于普通自动任务；清空联系人具有独占联系人写入锁，不受普通优先级规则打断。平台要求等待时保存恢复时间；明确隐私或权限错误直接记录；授权失效暂停该账号任务。不存在承诺安全的固定每日数量。程序重启后，未确定结果先核对，避免重复执行。

任务详情包含：参数快照、提交者、确认时间、每项状态、错误原因、已脱敏日志、执行时间。支持导出 CSV 结果。

### 3.6 AI 助手

入口：聊天右侧回复建议、任务中心自然语言建任务。

例：“把已标记同意入群的 12 位联系人生成项目群邀请任务”。AI 输出结构化草稿，缺少账号或目标群时要求补全，未确认不执行。模型只能调用预先定义的工具，不拥有任意终端或凭据访问权限。

AI 的上下文默认仅为当前选择会话中必要的消息；发送到外部模型前显示所选服务和数据范围，账号凭据永不进入提示词。可关闭 AI，关闭后不影响聊天和手动任务。

### 3.7 设置与操作记录

设置：应用 API 凭据、存储位置、界面、通知、快捷键、AI 服务配置、上下文范围、日志保留时间、面板锁定、应用数据备份。联系人清空前的备份独立管理，首版没有联系人一键恢复功能。

操作记录区分人工与自动化，保存账号、对象、动作、时间、结果、关联任务；手机号默认脱敏，不记录验证码、密码或会话密钥。用户可清理本地缓存，但须提示影响搜索、附件和记录的范围。

## 4. 典型端到端流程

首次使用：初始设置 → 添加第一个账号 → 同步最近聊天 → 查看消息并手动回复 → 继续添加其他账号。最近聊天优先加载，历史数据逐步按需同步，不承诺首次立即下载全部历史。

日常聊天：全部账号查看未读 → 打开会话 → 核对发送账号 → 输入或采用 AI 草稿 → 发送 → 查看状态。不同账号的同名联系人不会合并成同一发送窗口。

批量整理：选择账号与联系人 → 删除联系人 → 预览影响 → 确认 → 在任务中心逐项查看结果。

群邀请：记录对方同意 → 选群与对象 → 校验权限和重复项 → 确认 → 执行 → 分类查看成功、隐私拒绝、已在群、等待、失败。

断线恢复：顶部提示受影响账号 → 暂停其任务 → 自动尝试恢复连接；授权失效则登录 → 核对进行中的结果 → 恢复同步及允许恢复的队列。

## 5. 关键异常与界面反馈

无账号：空状态显示“添加你的第一个账号”。无聊天：显示同步状态和刷新入口。无匹配结果：可清除筛选。历史加载中：局部占位，不阻塞输入。

网络断开：保留草稿，清楚显示离线；手动消息可保存为待发送，但恢复后发送前允许用户取消。平台等待显示具体恢复时间，不伪装成普通加载。

权限不足：说明哪个账号缺少什么权限。隐私拒绝：记录不可直接邀请，不自动换号。账号受限：停止受影响动作，显示官方返回信息及人工处理入口。

AI 超时：保留输入与已有草稿，允许重试。附件失败：保留失败项。批量部分成功：显示成功/失败/未执行数量。身份不明确：发送按钮不可用。

## 6. 数据与实现约束

建议技术方向（设计建议，非已确认）：本地网页前端 + Python 后台 + Telethon + SQLite。前端仅通过后台访问 Telegram，会话和 API 凭据不暴露到浏览器。通过持续连接推送新消息和任务进度。

核心实体：账号、会话授权引用、聊天、消息、联系人、账号联系人关联、标签、同意记录、群、任务、任务项、执行记录、AI 草稿。消息与聊天主键必须包含账号维度，避免跨号覆盖。

本地面板默认仅监听本机；若未来部署到服务器，需要新增访问登录、加密传输及明确的数据存储配置。备份需保护会话凭据；日志和结果导出不包含登录凭据。禁止同一会话文件被多个独立执行器同时修改。

Telegram 权限、隐私和等待要求由平台决定；客户端界面的账号位置限制与程序保存独立授权会话是两件事。具体平台能力须在实现时用真实账号小范围验证。本稿不承诺规避平台限制。

## 7. 版本范围

第一版必需：8 账号管理；手机号登录与会话恢复；聊天列表与实时文字消息；文字、图片、文件手动收发；联系人查询、添加、删除；每账号独立的多群选择、实时新消息监听、自动添加和仅预览；全量现有联系人批量邀请、逐人核实结果及整批暂停；账号全部联系人清空前停监听、备份、二次确认和逐项结果；任务预览、队列、暂停、结果；AI 草稿和自然语言任务草稿；基本设置、计数和最近动态。

第二阶段：按白名单 AI 自动回复；计划任务；跨账号全局搜索优化；更完整媒体体验；可选二维码登录；丰富标签和统计。

本稿不包含：语音/视频通话、秘密聊天、多客服协作及权限体系、手机专属界面、账号注册或购买、群成员列表批量抓取与历史发言补抓、绕过隐私或平台限制、完整复刻 Telegram 所有功能。

## 8. 验收标准

1. 能添加并区分 8 个账号，重启后有效会话无需重复输入验证码；失效账号有明确重新登录入口。
2. 每个聊天列表项、消息窗口和任务预览均可识别所属账号；快速切换不会把草稿发给另一账号的联系人。
3. 真实消息可接收、回复及显示发送结果；断线、上传和发送失败有可操作反馈。
4. 人工接管会阻止该会话新的 AI 自动发送，AI 草稿不会默认自动发送。
5. 联系人删除明确说明作用范围；操作记录不将其记为拉黑或清除聊天。
6. 邀请任务可呈现成功、权限不足、隐私拒绝及等待，不把接口返回当作全部成功。
7. 暂停和重启不会重复执行已成功项；结果未知项先核对或标记需人工检查。
8. 批量执行前展示账号、名单、动作及正文/目标群；未经确认的 AI 草稿不进入执行队列。
9. 账号凭据不出现在页面日志、AI 请求或任务导出中。
10. 1440×900 可完成登录、聊天和任务操作，1280 宽可通过折叠辅助栏使用。

| 计数、最近动态、错误原因、停止、退出与后台运行 | 监听 / 任务 / 设置 | 分账号与全局控制分别可辨认 |

不以“增加聊天功能”为由删减这些已有行为。旧版代码是否复用、会话文件格式是否兼容，需在开发时检查源码与配置，不能仅凭截图承诺直接导入。

## 12. 分账号隔离与配置模型

### 12.1 隔离边界

所有账号资源以内部稳定 account_id 关联，重命名不会丢配置。账号登录成功后校验真实 Telegram 身份，禁止将 A 号的 session 绑定到 B 号配置。一个账号只由一个后台连接执行器持有会话；聊天与监听共用此连接，不重复占用同一文件。

每个账号单独保存：会话引用、内部名称、监听群选择、群列表拉取时间、监听模式、已保存配置版本、当前运行配置快照、监听开始时间、运行批次、处理去重记录、计数、最近动态、联系人快照、邀请任务、清空任务、等待时间与错误。

应用级共享项：视觉设置、应用 API 凭据（允许以后扩展为每账号覆盖）、AI 服务配置、存储位置和全局暂停。全局项不得覆盖账号的监听群选择。

A、B 号可同时监听同一个群；同一发言者在 A、B 中分别判断是否已添加，不跨账号跳过或复用访问凭据。A 号限流只冻结 A 号受影响操作；设备整体断网则所有账号各自显示离线。

### 12.2 “拉取”的范围

首版的拉取包括：刷新该账号已加入的群、刷新该账号全部当前联系人、加载聊天历史供人工查看、核实邀请后的成员状态。监听处理器不读取聊天历史来补充自动添加，也不抓取群成员列表。

群列表与联系人显示最后刷新时间，可手动刷新。首次进入页面加载当前快照，并提供刷新；后台监听依赖新消息事件，不依赖轮询历史。人工聊天加载的旧消息不能进入监听添加队列。

### 12.3 配置保存与切换

选择群组或模式后出现“有未保存更改”；当前运行仍用旧配置，不悄悄应用。保存时校验账号与群访问状态，并建立新版本。运行中更改需提示“保存并应用到后续新消息”，在事件边界更新；未开始的旧配置添加任务取消并记录原因，已经提交的请求允许结束并如实记录。

切换账号时保留该账号页面草稿及未保存标识；不把 A 的群选择套到 B。配置草稿、已保存配置与正在运行的配置版本分别显示。保存配置不等于启动监听；新账号与程序冷启动默认不自动开始实际添加。

## 13. 分账号监听与自动添加

### 13.1 群组选择

只列出当前账号已加入且可访问的群；以群名或标准化群 ID 搜索，ID 匹配不能依赖可改名的名称。多选、取消、仅选当前筛选结果、清空选择；按钮明确作用范围。显示已选总数及当前筛选命中数，隐藏在筛选外的已选群不会被意外取消。

刷新后失效或退出的群标为不可用，不替换为同名群。不可用群不处理消息，保留配置引用并提示重新选择。未登录、未选可用群、配置未保存时不能启动，旁边解释具体原因。

### 13.2 运行与处理流水线

启动时记录当前账号、配置版本、运行批次与开始边界；只接收启动之后来自已保存群组的新消息。启动前消息、离线补发的历史更新、编辑消息和服务消息不作为新发言者触发源。底层库恢复更新时也必须应用此边界，不能误处理积压历史。

收到新消息后按以下顺序：检查运行状态与配置 → 检查群范围与时间边界 → 识别真实发言用户 → 排除自己、机器人、匿名/频道身份或无法识别身份 → 查询联系人与按账号去重 → 若仅预览则记录候选 → 若实际添加则进入本账号写入队列 → 调用添加 → 记录明确结果。

仅预览允许读取验证所需资料，但不执行联系人写操作、不发送私信、不发邀请；预览不计入“已添加”，不写入实际成功去重表，之后切换实际添加时仍可处理未来新消息。预览模式不是历史采集功能。

添加是单向联系人操作，不表示互加或同意邀请。程序不主动增加手机号可见例外；对方可见信息仍受用户已有 Telegram 隐私设置影响。

### 13.3 去重与重试

消息去重键包含 account_id、群 ID、消息 ID；同一人不同群的新消息，通过 account_id + Telegram 用户 ID 去重并防止同时排队。成功添加与已确认现有联系人可持久化，失败与预览不能写成成功。成员资料解析须使用当前账号的有效引用。

用户重复发言可增加消息计数，但同一候选已排队时仅记录跳过，不创建并发重复添加。明确失败保留原因；不无限重试。结果未知先核实联系人状态，再决定重试或标记人工处理。

手动删除联系人不自动清除“已处理”记录，防止刚删除就再次添加。重新允许该对象处理需在高级控制中明确重置本账号的对应记录；全量重置需要说明影响，不随清空联系人自动发生。

### 13.4 运行状态与计数

状态：未配置、就绪、仅预览运行中、实际添加运行中、停止中、已停止、等待平台允许、离线、需重新登录、错误暂停。登录状态与监听状态分栏显示，在线不代表正在监听。

本次运行计数：成功添加数、跳过事件数、预览候选次数、失败数、待处理数；可展开跳过原因。预览次数按通过排除条件的候选事件计数，同一人多次发言可多次预览，界面明确为“候选次数”，不称“人数”。统计按运行批次保存，停止后仍可查看；另可查看累计数据，默认不与本次混算。

最近动态字段：时间、账号、群、发言者、处理模式、配置版本、结果、原因。默认只显示当前账号，可切换全局；预览结果明确“未修改联系人”。群消息原文默认不作为操作日志永久保存。

### 13.5 停止、断线与恢复

停止本账号：先关闭事件入队，再取消未执行添加项，等待在途请求结束或标记未知；显示“停止中”直至达到停止边界。已成功添加不撤销。

断线期间停止接收；重连后设新接收边界，不补抓断线期间的发言。平台等待期间停止新增实际添加，显示恢复时间，不积累无限队列；恢复前再次校验状态。关闭浏览器不会停止监听；Mac 休眠、离线或后台退出会中断工作。

程序重启可恢复登录和配置，但监听显示“已停止 · 待手动启动”；不自动恢复清空任务或实际添加。不会把重启期间消息补入添加队列。界面提示运行需保持设备唤醒及联网，不承诺关机仍运行。

## 14. 批量邀请完整规则

### 14.1 名单与准备

固定所属账号 → 刷新其全部现有联系人 → 搜索和勾选 → 选择目标群 → 确认已获所选对象同意 → 预览 → 开始邀请。全部现有联系人包括旧联系人、手动添加与监听添加者，不仅限于本软件新增。

未注册号码、已删除或无法解析对象显示原因且不可邀请，不悄悄丢失行。跨页勾选显示确切总数，可查看完整已选清单；全选明确“当前页”或“全部筛选结果”。同意勾选绑定账号、目标群与名单快照，任何一项变化后重新确认。仅勾选同意不等于平台权限已满足。

预览展示：账号、目标群名称及 ID、已选与可执行数量、排除/已在群/未知项、权限检查结果、确认时间。预览不发送邀请。只对目标群执行本批次，创建后不可静默换群或换号。

### 14.2 逐项结果

| 结果 | 判定 | 后续 |
| --- | --- | --- |
| 已核实加入 | 提交后通过可用成员查询或可靠成员事件核实 | 计已加入，不重邀 |
| 原已加入 | 邀请前可核实其已在群 | 跳过，不重复邀请 |
| 受限 | 明确的对象隐私/邀请限制 | 记录原因，继续下一位 |
| 未核实 | 请求可能完成但缺乏足够证据确认成员状态 | 不当成功、不自动再次邀请；提供重新核实 |
| 失败 | 明确未成功的单人错误，如无效身份 | 记录原因，继续下一位 |

若当前权限不允许成员核实，应在预览提示，执行后保留未核实，不能以 API 无异常冒充已核实加入。核实动作有界限与等待处理，不无限查询。

### 14.3 批次控制

单人失败、受限或未核实可继续下一位。账号限流、断网、授权失效、账号级限制或目标群权限失效暂停整批；显示影响范围与原因，不把暂停当作对象受限。恢复时检查登录、权限、等待时间、联系人可解析性，并处理未知在途结果。

停止：不再执行剩余对象，已完成邀请不撤销，在途请求仍可能完成。停止后保留完整结果，新建后续任务时排除已核实加入和原已加入者；未核实项先核实，不直接重邀。不得自动改发私信邀请链接或换另一个账号继续。

支持本账号及全局任务视图、结果筛选和导出。统计满足：已处理 + 未执行 = 总数；五类已处理结果合计 = 已处理。进行中另列，不混进成功数。

## 15. 全部联系人清空与任务互斥

### 15.1 范围和备份边界

清空目标是指定账号的全部联系人，包括原有联系人、自动添加联系人及已同步的未注册号码；不删除聊天、不拉黑、不移出群，不影响其他账号。

本机备份仅包含可导出的已注册联系人，不包含未注册号码，首版无一键恢复。确认页同时展示总删除数、已注册数、未注册数、实际备份条数。备份保存失败、无法重新读取或无法准确确定删除范围时禁止进入最终确认，不显示虚假的零条。

删除接口对保存联系人及未注册号码的能力须在真实环境验证；如果不能覆盖完整范围，任务必须显示“不支持完整清空”，不能把已注册联系人删除完成显示为全部完成。

### 15.2 严格执行顺序

1. 选择账号，读取清空说明，点击“准备清空”，此时不删除。
2. 停止本账号监听添加，取消未执行添加项，处理在途结果，锁住本账号所有联系人写入入口。
3. 检查相关邀请任务：运行中的先暂停，用户确认处理边界；不影响其他账号。手动聊天仍可使用。
4. 读取最新完整联系人快照与未注册号码统计；读取失败则停止准备。
5. 原子写入本机备份并校验可读性、条数和文件摘要，显示位置；备份不包括会话密钥。
6. 展示二次确认页：账号及手机号脱敏、范围及数量、备份缺口、无恢复功能。需勾选理解并输入账号名称；最后按钮“确认清空 N 条联系人”。
7. 最终确认前再次检查快照是否变化。变化则作废确认、重新读取并备份；最终确认默认 5 分钟过期，此为设计建议。外部客户端也可能修改联系人，不宣称跨客户端完全锁定。
8. 执行期间逐项记录、支持停止；完成后重新读取可验证范围，显示已删除、失败、剩余、未核实，不因请求已提交就称清空成功。
9. 释放本地写入锁，监听保持停止；用户手动决定是否重新启用。保留去重记录，避免清完马上重加。

### 15.3 取消、失败与退出

确认前取消不删除数据，但监听保持停止并明确提示；已保存备份保留。执行中停止不撤销已删除项。限流/断网暂停，恢复前核实剩余数据与备份覆盖；新变化重新确认，不自动扩大原删除范围。应用重启不自动续删，需人工检查。

全局暂停阻止新自动化写入及监听入队，在途请求收尾；恢复全局暂停不自动启动此前已停止的账号，不自动续删，批量邀请先检查。退出程序入口列出全部运行任务，确认后停止接收、保存记录并退出后台；关闭网页仅关闭视图，不等于退出程序。

## 16. 详细布局与交互规范

统一采用旧版青绿色视觉方向。桌面基准 1600×1000：主导航约 72 px、账号栏约 200 px、内容自适应，重要操作置于内容顶部或固定底栏，不要求滚到长页面最下方才能停止。数字仅为设计基准。

监听页：顶部账号身份与运行状态 → 本次统计 → 左侧群组选择、右侧配置和运行控制 → 最近动态。群列表可独立滚动；运行控制固定可见。修改配置后显示草稿与运行版本差异。

批量邀请：顶部账号和目标群 → 四步向导 → 名单/逐项结果主表 → 右侧批次确认摘要 → 底部本批控制。选择、预览、运行和暂停为独立状态，不在运行时继续修改名单。预览和运行可复用同一表格但必须切换状态标签。

清空页：账号范围 → 五步流程 → 前置检查与备份卡 → 二次确认卡 → 删除进度及结果。最终确认按钮使用克制红色；其他普通动作使用青绿，避免误点。危险确认不使用默认 Enter 快捷提交。

账号页：在线与监听分开统计；每行展示模式、所选群数、配置版本、任务摘要。新增账号用分步抽屉，旧号重登绑定旧 account_id，登录为不同真实身份时禁止覆盖，提示新增账号。

等待登录：已保存账号列表仍可查看；目标账号的群选择和启动禁用并说明原因。两步密码、验证码不出现在普通日志或账号列表。空、加载、失败、等待、部分成功状态均提供有意义文本，不只用颜色。

## 17. 新增验收场景

11. A 号实际监听三个群、B 号仅预览两个群同时运行，切换页面不改变模式、配置或计数归属。
12. 修改 A 号未保存群选择不影响运行；保存应用后有新版本与清楚的生效边界，不误用 B 号群 ID 或身份。
13. 启动前消息、聊天页加载的历史、重连补发历史、编辑与服务消息不触发自动添加。
14. 自己、机器人、匿名身份、已有联系人、成功处理过的人分别有跳过原因；同一人跨群不会产生并发重复添加。
15. 预览不会修改联系人或写成功去重；之后实际模式遇到该人的新消息可以正常处理。
16. 联系人刷新涵盖本账号所有现有联系人，原有联系人可被勾选邀请；账号变化清除旧批次选择及同意确认。
17. 邀请五类结果按核实证据判定；单人失败继续，账号限流/断网/权限失效暂停整批；恢复不会重邀已完成项。
18. 清空准备先停本账号监听并处理在途添加；备份失败禁止删除；未注册号码缺口与无恢复能力在确认前可见。
19. 清空不影响其他账号、聊天记录或群成员身份；外部修改使确认作废；结束或取消不自动启动监听。
20. 页面关闭后后台继续；退出程序会保存任务边界；重启保留登录配置但不自动实际添加或续删。
21. 本次计数与累计分开；预览次数不冒充人数；邀请结果数量守恒；每条记录可追溯账号及运行批次。
22. 旧会话与配置未经过身份和格式验证不得导入或覆盖；账号重命名不丢监听范围。

## 18. 旧版迁移与开发前核验

用户当前提供的是截图和功能描述，并未完成旧版源码检查。开发前读取旧版配置格式、会话保存位置、备份格式、群 ID 表示及数据版本；复制原始文件做迁移备份后在新存储中导入，保留旧文件，不原地升级。

导入预览显示：来源、真实账号身份、可迁移字段、不能迁移字段、会话能否恢复。仅用户明确选择的账号可导入；不能移植的运行统计或去重记录应如实说明，不能伪造迁移成功。迁移后所有监听停止，用户核对配置后启动。

若只复用用户功能而重新实现，文档中的行为仍须验收。真实平台验证重点为：未注册保存联系人完整读取/删除、邀请后成员核实、账号范围错误与等待恢复。无法满足的能力必须在开发评审中明确，而非在界面中隐藏。
