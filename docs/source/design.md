# TG 多账号工作台 · 详细界面设计 V0.2

日期：2026-10-22｜配套：完整需求 V0.2｜交付性质：高保真概念图与交互规格，不是已运行程序。

## 1. 全局结构

主导航与账号栏在页面间保持稳定，内容随导航与账号变化。任何会修改数据的页面，顶部必须显示账号内部名、头像与脱敏手机号，确认面板再显示一次。鼠标悬停仅用于补充解释，关键范围不能只依赖悬停提示。

主导航：聊天、监听、联系人、群组、任务、账号、设置。群组可作为聊天中的群聊子入口；联系人有“列表 / 批量邀请 / 联系人清理”页签。未读、监听状态和登录状态分开表示。

账号栏示例：

| 账号 | 连接 | 监听 |
| --- | --- | --- |
| 客服01 | 在线 | 实际添加 |
| 客服02 | 在线 | 仅预览 |
| 项目01 | 在线 | 已停止 |
| 项目02 | 在线 | 实际添加 |
| 运营01 | 在线 | 已停止 |
| 运营02 | 在线 | 已停止 |
| 备用01 | 在线 | 已停止 |
| 备用02 | 待登录 | 不可启动 |

“全部账号”只适用于聚合聊天、动态和任务查询，不允许在此状态直接配置监听或清空联系人，需选择一个明确账号。批量邀请每批也只属于一个账号。

视觉：浅灰背景、白色内容卡、深色文字、青绿主操作；绿色表示正常、蓝色表示预览、琥珀色表示等待/暂停、红色仅用于危险删除和失败。状态均有文字，不仅靠颜色。正文建议 14–16 px、标题 22–28 px，表格行高约 44–48 px。整体沿用旧版清爽青绿色方向。

## 2. 图 01：分账号监听控制台

对应文件：01-分账号监听控制台.png。展示客服01实际添加运行中的状态；其他账号保留各自状态。

### 页面区块

1. 标题区：监听与自动添加、账号身份、模式、运行状态、当前运行版本。
2. 本次运行指标：已添加、已跳过、预览候选次数、失败/待处理。点击指标可筛选下方动态。可展开累计统计，默认显示本次。
3. 群组选择卡：刷新、名称/ID 搜索、多选列表、全选当前结果、清空选择、已选数、上次刷新、保存配置。
4. 配置卡：仅预览/实际添加、处理范围说明、跳过规则、单向添加说明。
5. 固定控制区：启动仅预览 / 启动实际添加；运行后改为停止本账号。模式变化需保存应用，不能在后台偷偷生效。
6. 最近动态：时间、群、发言者、模式、结果、原因，可展开错误详情；本账号/全部账号切换。
7. 底部环境提示：关闭网页不会停止后台；设备需要唤醒与联网；退出程序入口在全局菜单。

### 状态与操作

| 状态 | 主操作 | 可见说明 |
| --- | --- | --- |
| 未登录 | 登录本账号 | 选群与启动禁用 |
| 已登录但未选群 | 选择并保存群组 | 启动禁用，说明原因 |
| 有未保存修改 | 保存 / 放弃修改 | 显示运行版本与草稿差异 |
| 已停止 | 仅预览 / 启动实际添加 | 显示上次运行结果 |
| 预览中 | 停止本账号 | 蓝色“未修改联系人” |
| 实际添加中 | 停止本账号 | 青绿运行标识 |
| 停止中 | 等待在途请求处理 | 禁止重复启动 |
| 限流等待 | 查看原因 / 停止 | 平台允许恢复时间 |
| 离线 | 查看连接 / 停止 | 不追补离线发言 |
| 错误暂停 | 修复后检查 / 停止 | 显示账号级原因 |

保存并应用的确认文案：“将后续新消息切换为配置 v5，取消尚未开始的旧配置处理；已提交请求可能完成。”

仅预览切换到实际添加前明确显示账号和群范围。预览候选不自动搬入实际添加队列，实际模式只处理之后的新消息。

## 3. 图 02：批量邀请与结果核实

对应文件：02-批量邀请与结果核实.png。图示执行中发生断网后整批暂停的结果页，不是假设全部成功。

### 四步流程

第一步“刷新并选人”：顶端锁定账号，刷新其全部现有联系人；名称/用户名搜索，来源筛选“全部 / 原有 / 监听添加 / 手动添加”；复选框、全选范围、已选清单。原有联系人必须能出现在名单。未注册号码显示“不可邀请”。

第二步“目标群与同意确认”：只能选择该账号可访问的目标群，显示群名及 ID、权限检查时间；勾选“已确认所选联系人同意加入此群”。切换群、账号、名单后此确认失效。

第三步“执行前预览”：只读名单、排除原因、账号、目标群、可执行数、已有成员数、未知数和核实能力；按钮“返回修改 / 确认开始”。不在这一阶段调用邀请接口。

第四步“执行结果”：表格锁定名单，逐项更新；右侧显示本批确认记录、账号、群、时间及控制按钮。顶部总进度与分类数守恒。支持“仅看受限/未核实/失败”筛选和导出。

### 结果与控制

结果仅使用：已核实加入、原已加入、受限、未核实、失败；排队/执行中独立列示。说明列展示核实时间与错误原因，不仅显示一个彩色徽章。

未核实行操作是“重新核实”，不能默认“再次邀请”。失败行只有在确定未成功且条件允许时提供重试。单人失败继续；账号限流、断网或群权限失效时标题区显示整批暂停原因。

暂停时按钮：“恢复前检查”“停止本批次”。点击检查展示授权、网络、群权限、等待时间与在途结果；条件通过后才恢复未执行项。停止确认文案：“将取消剩余 4 项，已完成邀请不会撤销，在途请求仍可能完成。”

图示数据：总数 12，已处理 8，未执行 4；已核实加入 3、原已加入 2、受限 1、未核实 1、失败 1。

## 4. 图 03：联系人清空二次确认

对应文件：03-联系人清空二次确认.png。图示已经完成准备和备份，停在最终二次确认，尚未删除。

### 五步流程与界面

1. 停止自动添加：明确本账号，等待在途写操作结束；必要时暂停本账号邀请任务；显示互斥锁已建立。
2. 读取联系人：显示读取中、读取完成或失败；失败时不能继续。
3. 保存本机备份：显示文件名、可打开位置、条数、创建时间与校验结果。文件只含可导出的已注册联系人，不含登录凭据。
4. 再次确认：左侧准备检查表，右侧删除范围与二次确认。输入账号内部名，两条风险理解勾选；最终动作显示数量。
5. 删除结果：已删除、失败、剩余、未核实；支持查看细节和停止未执行项，不提供一键恢复。

### 最终确认文案

标题：“仅清空 客服01 的全部联系人”。

范围：“包含原有联系人、自动添加联系人和已同步未注册号码；不删除聊天记录、不拉黑、不移出群；其他账号不受影响。”

示例数量：“删除范围 356 条，其中已注册联系人 340 条、未注册号码 16 条；备份 340 条。”

显著提示：“备份不包含 16 条未注册号码，目前没有一键恢复。”

勾选一：“我理解备份不完整且没有一键恢复。”

勾选二：“我确认只清空客服01的联系人。”

输入：“输入账号名称确认”。

按钮：“取消”“确认清空 356 条联系人”。账号身份、数量、备份或快照失效时重新准备，不沿用旧确认。最终按钮不接受 Enter 默认提交。

取消后显示“未删除联系人，监听仍已停止”，不能悄悄恢复自动添加。清空完成后也保持停止。打开备份位置仅为查看文件，不表示具备自动恢复能力。

## 5. 图 04：账号管理与独立配置

对应文件：04-账号管理与独立配置.png。展示八账号状态表及添加账号的两步验证抽屉。

账号表字段：内部名称/用户名/脱敏手机号、连接、监听模式、所选群数、已保存配置版本、任务摘要、操作。在线数与监听中数分别统计。

每行操作：打开聊天、打开监听配置、查看本账号任务、重新连接、退出登录、从工作台移除。危险动作放二级菜单，避免与“打开”紧邻。

登录抽屉四种主要状态：

| 状态 | 字段与操作 | 失败反馈 |
| --- | --- | --- |
| 手机号 | 国家区号及手机号；获取验证码 | 格式错误、发送受限 |
| 验证码 | 脱敏号码、实际渠道、验证码；验证 | 错误、过期、平台等待 |
| 两步验证 | 密码显示/隐藏；验证并保存会话 | 密码错误，不回显密码 |
| 成功 | 真实身份、内部名称；进入配置 | 身份不匹配禁止覆盖旧号 |

返回或取消不会把验证码/密码写入日志；错误在字段附近显示。保存成功后账号出现在左栏，默认未启动监听。已有会话有效时恢复，不要求每次验证码；失效则在该账号行重新登录。

旧版导入：按钮“检查旧版配置”，选择旧数据后先预览身份及兼容字段；首版是否能直接复用需读源码验证，不在图中承诺一键迁移。

## 6. 聊天、联系人列表、群组、任务与设置的保留设计

聊天沿用前版四区域布局：账号栏、聊天列表、消息窗、可折叠资料与 AI 草稿。发送区始终显示所属账号；不提供首版语音/视频通话入口。监听任务在后台独立运行，打开聊天不会停止监听。人工接管默认仅控制 AI 回复，不等于停止该账号监听添加，两者开关必须分开命名。

联系人列表字段：姓名、用户名、可见手机号、所属账号、来源、标签、邀请同意记录；支持手动添加、CSV 导入预览、删除选中。右上普通按钮“批量邀请”，危险功能“清空本账号全部联系人”放清理子页。删除选中与清空全部不能共用模糊的“删除”确认。

群组页面展示账号可访问群及权限，进入聊天或跳转为监听选择；不能跨号直接套用相同名称的群。没有成员列表批量抓取或历史发言补抓按钮。

任务中心按账号、类型、状态筛选，监听运行摘要与一次性邀请/清理任务区分展示。连续监听没有伪造固定百分比；邀请/清理显示逐项进度。详情保留参数、配置版本、确认记录、在途状态和结果。

设置页面包含本地路径、AI 服务、日志与应用凭据。全局菜单“暂停全部自动化”与“退出后台程序”分开；退出时展示运行账号和任务。网页关闭无需退出确认，因为不停止后台；程序退出需要展示受影响工作并安全保存边界。

## 8. 本轮图稿核对记录

四图已完成视觉检查：当前账号、独立配置、邀请五类结果、清空前备份缺口及二次确认均有对应展示。以下生成图细节不作为最终实现依据：

- 监听图中的跳过项为固定规则标签，不是允许取消的复选框；应统一渲染为只读标签。最近动态可以查看之前配置版本，但必须补充模式与版本字段；当前未选群不能产生当前版本新事件。
- 邀请图执行中出现“刷新联系人”仅允许刷新查看，不改变已锁定名单；正式界面优先禁用并提示“本批名单已锁定”。图中的额外“重复联系人”等页签不是新增首版功能。
- 清理图左侧高亮应为“联系人”，不是“账号”。“删除 356 条联系人”正式文案使用“清空 356 条联系人记录”，避免将未注册号码当作可邀请用户。
- 图中年份、账号在线数量与示例动态为独立虚构场景，不是实时状态。正式实现使用真实数据，数量一致性按完整需求验收。
- 监听图的“暂停接收”如保留，语义与全局暂停一致：关闭新事件入队、保留运行批次，恢复设新接收边界且不补追暂停期间消息；“停止本账号”结束本次运行并取消未执行项。二者均不撤销已完成添加。
