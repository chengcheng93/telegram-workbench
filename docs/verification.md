# V0.2 开发与验收记录

客户端日期：2026-10-22。应用版本：3.0.0。依据 `source/requirements.md`（345 行）、`source/design.md`（164 行）和配套四张设计图。

## 当前结论

完整七页工作台已实现并部署到本机。独立环境中的 **314 项 Python 测试通过**（最终重跑 6.540 秒），**48 项 Node 测试通过**；依赖检查、27 个 Python 文件 AST、JavaScript 语法和 Git 空白检查通过。测试使用临时目录与模拟 Telegram / AI，不代表真实平台操作成功。

界面已完成七页 1440×900 / 1280×900 浏览器操作验收。基线 26 项通过，其中 22 项为模拟双账号交互、4 项为真实临时空面板与未发码登录抽屉。追加媒体定向回归 **6/6 通过**：fetch/blob 等待期间切账号、切聊天或锁定均不会弹出旧附件或下载；失效对象 URL 立即回收；Chrome 下载保留中文、空格及扩展名。追加测试直接使用本地产品静态文件和拦截媒体，没有访问或重启真实服务；源码在测试前后相同，无页面或控制台异常。原 26 项未因这次静态修复重复运行。

部署后的真实服务已通过鉴权 HTTP 读取验证：版本 3.0.0，应用 API 已配置；另用独立无头浏览器打开真实面板并截图，无 JavaScript 异常。没有自动导入旧账号会话或群选择；安装只复用此前已保存的应用 API 配置，并在新私有目录保存配置备份。

**两个真实账号已由用户在本机授权，双账号登录及只读检查通过。** 本机手机号、验证码、密码、API Hash、会话密钥及真实联系人不写入本文。用户指定后续真实检查优先使用 `运营测试账号`，个人账号谨慎处理；本轮未为个人账号主动请求新增云端读取，未执行任何 Telegram 写入或重启服务。

## 真实双账号检查（2026-10-22）

- 两号均 `logged_in=true`、`connected=true`、`stage=ready`，内部账号 ID 和已核实 Telegram 身份各不相同。公共接口的授权字段为 `logged_in`，不是 `authorized`。
- 两个账号的 session 文件分别存在且权限为 600；本地缓存会话逐行归属正确，聚合视图保留账号维度，没有合并同 ID 对象。两号监听均停止。
- 仅对 `运营测试账号` 真实刷新最近会话及群组，读取现有群一页历史消息，均正常且归属匹配；读取收藏夹返回空历史也是正常响应。最近会话最多 100 项、消息每页最多 50 条，不冒充完整云端同步。
- 对 `运营测试账号` 一个既有群显式读取权限，结果为不能邀请，有原因和检查时间。该结论仅适用于抽样群，不代表该号所有群都不能邀请。
- 新建独立无头浏览器直接访问真实本机服务，5 项操作检查通过：两号在线显示、运营号缓存会话切换、个人号缓存会话切换、聚合归属、无写入或额外云端读取请求。实际仅调用本地 `list_chats`；页面和控制台错误均为零。没有操作用户前台页面或记录真实聊天正文。
- 本轮未发送消息、上传媒体到 Telegram、添加或删除联系人、邀请、启动实际监听、重启服务。真实双账号草稿切换、收发与平台写入、重启恢复仍可由用户在可控场景继续验收；对应实现边界已有模拟测试，不能把模拟通过称为这些实际操作已执行。

## 需求逐条核对

“覆盖”表示实现、模拟行为或界面操作证据；真实 Telegram 验收另列，不混淆两者。

| 验收项 | 当前实现与证据 |
| --- | --- |
| 1. 八账号与会话恢复 | `test_accounts.py`：容量、独立文件锁、重复身份与错绑拒绝、重命名、有效会话恢复、成功态关闭不擦除会话。真实双账号授权、身份与会话文件隔离已核实；真实重启恢复未执行。 |
| 2. 身份与草稿隔离 | `test_chats.py`、`ui.test.cjs`、浏览器：账号+聊天主键，聚合会话绑定发送身份，快切和迟到响应不串号。 |
| 3. 收发与失败反馈 | 聊天模块测试文字、回复、图片/文件、上传取消、发送状态、明确失败与未知结果、编辑/撤回权限。真实平台与媒体收发待用户测试。 |
| 4. AI 草稿与人工接管 | `test_ai.py`：默认关闭、数据同意、受限上下文、超时、接管使在途草稿失效；采用仅写草稿，不发送。真实供应商请求未执行。 |
| 5. 删除联系人范围 | `test_contacts.py`、`test_tasks.py`：只删除所选账号指定对象，不调用拉黑/删聊天/踢群。 |
| 6. 邀请真实分类 | `group_invites.py`、`test_invite_rpc.py`：成员预检和事后核实、权限、隐私、等待；接口无异常不等于加入。真实群权限待验证。 |
| 7. 暂停重启不重放 | RPC 前持久 journal；重启遗留在途转未核实。任务 outbox 所有权、固定 request_id、5xx 不确定写入、只读核实与合法失败重试有回归。 |
| 8. 预览与明确确认 | 手动五类型任务及 AI 任务草稿均走账号/对象/正文或目标群预览；确认 token 绑定账号、身份、范围和有效期。 |
| 9. 凭据边界 | 快照、日志、AI 请求、导出不含凭据；loopback/Host/Origin/token/面板锁检查；锁后 HTTP、媒体迟到结果有世代栅栏。 |
| 10. 桌面尺寸 | 浏览器 1440 / 1280 七页无页面级横向溢出；较窄窗口辅助栏可折叠，表格允许内部滚动。 |
| 11. A 实际/B 预览并行 | `test_listeners.py`：同群同用户分账号处理；模式、计数、运行批次独立。 |
| 12. 配置草稿/保存/运行版本 | CAS 保存、运行时应用边界、旧排队取消与已提交结果保留；浏览器切号保留未保存修改。 |
| 13. 只处理实时新发言 | 启动微秒边界、连接 epoch、消息 ID、source/type 检查；拒绝历史、服务、编辑和重连积压。 |
| 14. 排除与并发去重 | 自己、机器人、匿名、现有/已处理者有原因；用户排队唯一，实际提交前再次检查版本与 gate。 |
| 15. 预览无写入 | 预览不写联系人或成功去重；后续实际模式只处理之后的新事件。 |
| 16. 完整现有联系人名单 | GetContacts(hash=0) 完整校验，原有/手动/监听联系人可选；保存号码未知行保留且不可邀请。切号清名单和同意。 |
| 17. 邀请控制 | 五类逐项结果，单人失败继续，整体错误暂停；跨任务占位、恢复检查、未核实重核、数量守恒与 CSV 导出。 |
| 18. 清空前停止与备份 | 联系人 gate 先关闭，排空在途；备份原子写入并回读/条数/摘要校验；范围未知不能最终确认。 |
| 19. 清空隔离与外部变化 | 每账号锁，聊天与其他账号可用；名称+两勾选、最新快照与首次 RPC 前再核对；取消/结束保持监听停止。 |
| 20. 后台与重启 | 浏览器关闭不发送停止指令；明确退出预览绑定受影响工作；冷启动不实际添加、不续删、不重放离线消息。 |
| 21. 统计与归属 | 本次/累计分开，候选按次数，事件含账号/run/version；处理数+未执行=总数，五类结果不冒充全部成功。 |
| 22. 旧版导入 | `test_migration.py`：来源锁、私有备份、SQLite 快照、格式/身份/摘要/TTL、重复身份、并发与失败回滚；未真实导入旧会话。 |

## 独立审查闭环

独立整体审查发现并关闭 6 项 P1、3 项 P2：成功态误取消授权、任务消息绕过、锁中途回包泄露、新号码解析、服务器不确定错误重试、预览身份映射变化、历史消息搜索、群信息权限、手动任务/任务搜索。

修复经单独故障复现及针对性测试复验。追加 UI 闭环包含空 target 的任务预览、无交互 Toast 不遮挡按钮、任务 outbox 跳到任务中心、缓存范围如实说明。清缓存保留附件元数据、未发送草稿、任务和撤回墓碑。

媒体收尾先以实际控制函数复现 4 项失败，再修复请求世代守卫与 RFC5987 文件名；纯文件名解析另有 10 项红→绿测试，随后完成上述 6 项真实浏览器模拟交互回归。媒体修复只更新静态文件，未中断已打开的真实账号登录流程；完成登录后刷新即可加载最新界面。

独立审查另对媒体实际 diff 和新增 14 项回归复核，未发现重要遗漏；选测共 15/15 通过，其中另匹配一项已有任务参数测试。

## 平台能力与真人验收

- 已保存号码导出需要 takeout；返回号码没有注册状态。无法准确核实范围时显示“不支持完整清空”，不是零条，也不称全部完成。
- 暂未使用真实账号执行添加、删除、邀请、发消息或外部 AI 请求。软件内的成功必须以实际平台证据为准。
- 用户已在“账号管理”登录两个账号，身份、会话文件和缓存归属已核实。后续可用 `运营测试账号` 的可控测试会话验证少量收发/预览；个人号慎重。验证码和两步密码仅填本机面板。
- 八账号容量/隔离已有模拟覆盖，长期多账号负载、不同网络、账号限制和供应商兼容性仍需实际运行观察。
