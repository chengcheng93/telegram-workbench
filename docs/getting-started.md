# 新手上手指南

这份指南面向第一次从 GitHub 下载项目的人。按顺序完成即可，不需要先学习前端开发；安装过程中会用到 macOS 自带的“终端”。完整功能概览见 [README](../README.md)，出错时查看[常见问题](troubleshooting.md)。

## 1. 确认电脑与准备事项

| 环境 | 当前情况 |
| --- | --- |
| macOS + Python 3.14 | 已验证，以下步骤以此为准 |
| Linux | 可以尝试源码启动，但尚未完整实测，桌面与浏览器行为需自行验证 |
| Windows | 当前不支持，后台依赖 `fcntl`；这些命令不适用于 Windows 原生运行 |

准备好你本人拥有的 Telegram 账号，以及能正常连接 Telegram 的网络。Node 不是运行依赖，不需要为使用工作台安装它。

先打开“终端”，运行：

```sh
python3.14 --version
```

看到 `Python 3.14.x` 即可继续。若提示找不到命令，从 [Python 官方 macOS 安装说明](https://docs.python.org/3.14/using/mac.html)获取 Python 3.14 安装程序，安装后关闭并重新打开终端，再检查一次。不要替换或修改 macOS 自带的 Python。下文明确使用 `python3.14` 创建环境，避免误用系统旧版本。

## 2. 下载项目：两种方式选一种

### 方式 A：下载 ZIP，适合第一次使用

1. 打开[项目 GitHub 页面](https://github.com/chengcheng93/telegram-workbench)。
2. 点击绿色 **Code** 按钮，再选 **Download ZIP**。
3. 下载完成后解压，把得到的项目文件夹放在便于找到的位置。
4. 打开该文件夹，确认里面能看到 `server.py`、`requirements.txt` 和 `web` 文件夹。

不要直接在压缩包里运行文件。GitHub 的操作说明见[下载源码压缩包](https://docs.github.com/en/repositories/working-with-files/using-files/downloading-source-code-archives)。

### 方式 B：已经安装 Git 的用户

在准备保存项目的位置打开终端，运行：

```sh
git clone https://github.com/chengcheng93/telegram-workbench.git
cd telegram-workbench
```

两种方式得到的源码相同，不需要两种都做。

## 3. 让终端进入正确文件夹

如果用了 ZIP，或重新打开了终端：输入 `cd` 后加一个空格，先不要按回车；把 **包含 `server.py` 的项目文件夹**从 Finder 拖进终端，再按回车。拖入时终端会处理路径中的空格，不要再手动拼接路径。

检查当前目录：

```sh
ls server.py
```

应当显示 `server.py`。如果提示找不到文件，先回到 Finder 找到正确的内层项目文件夹，再重复上面的操作。之后的安装、启动命令都在这个目录执行。

仓库中的 `TG 多账号工作台.app` 和 `启动.command` 依赖原开发目录里的运行环境，**不是下载后即可通用安装的应用**。新用户请继续下面的源码启动步骤。

## 4. 安装一次，然后启动

下面的每行都是一条命令，逐行粘贴并按回车；上一行结束后再运行下一行。

先创建项目专用的 Python 环境并安装依赖：

```sh
python3.14 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
```

`.venv` 是这个项目自己的运行环境，不需要管理员权限。激活后，终端提示符通常会出现 `(.venv)`；下文的 `python` 会使用这个环境。

然后明确指定本机数据目录并启动：

```sh
export TG_WORKBENCH_STATE_DIR="$HOME/.local/share/telegram-workbench"
python server.py
```

请保留这条 `export` 的写法：`$HOME` 会自动指向你自己的用户目录。**以后每次启动也要使用同一个数据目录**，否则可能打开一个没有账号的新工作台。不要将这个目录放进项目、共享目录或公开仓库。

成功后会自动打开浏览器面板。终端会显示“本机工作台已启动”，并继续运行；此时没有新的命令提示符是正常现象，请让这个终端窗口保持打开。面板地址在本机 `127.0.0.1`，端口自动选择，还需要本次访问令牌；不要手工猜端口或只复制终端打印的地址。

如果页面没有自动打开，请先看[页面打不开或提示令牌缺失](troubleshooting.md)。不要双击 `web/index.html`，它不能代替后台服务。

## 5. 配置自己的 Telegram 应用凭据

1. 在浏览器打开 Telegram 官方的 [my.telegram.org](https://my.telegram.org/)，使用自己的账号登录。
2. 进入 **API development tools**，按页面要求创建应用，取得自己的 **API ID** 和 **API Hash**；如果已经有应用，直接使用现有应用的凭据。详细流程见 [Telegram 官方说明](https://core.telegram.org/api/obtaining_api_id)。
3. 回到本机工作台的“设置”，在 Telegram 应用凭据区填写这两个值并保存。API ID 是数字，API Hash 要完整复制；保存后的秘密不会回显。

这是你自己的 Telegram 应用凭据，不是 Bot Token，也不是从项目作者那里领取的公共密钥。工作台默认没有配置好的凭据。登录官网和登录工作台的验证码到达渠道都由 Telegram 决定，以平台提示为准。

API Hash、验证码、两步验证密码和会话文件只在可信本机处理，**不要发到聊天、问题报告或代码仓库中**。

## 6. 登录第一个账号

1. 打开“账号管理 → 添加账号”。
2. 输入完整国际格式手机号，包含开头的 `+` 和国家码，然后请求验证码。
3. 根据界面显示的实际渠道查收并输入验证码，不要假设一定是短信。
4. 如果账号开启了两步验证，再输入该账号的两步验证密码；它不是短信验证码。
5. 登录成功后设置内部名称，例如“账号 A”。核对真实身份、脱敏号码和连接状态。

登录会话与应用配置保存在刚才指定的本机私有数据目录，有效会话可在下次启动复用。**新账号默认停止监听**，登录本身不会开始自动添加。需要第二个账号时重复上述步骤，命名为“账号 B”；最多可添加 8 个本人账号。

## 7. 第一次先做小范围检查

先只做本机草稿和只读检查，不用客户名单做首次验证。

1. 在“设置”取消勾选“Enter 发送消息”（如当前开启），点击“保存界面设置”，避免检查草稿时误发。需要换行时可使用 `Shift+Enter`。
2. 选“账号 A”，刷新并查看自己的聊天与群组，核对顶部身份。打开一个会话，输入“账号 A 草稿”，不要点击发送。
3. 切到“账号 B”，查看它自己的聊天与群组，输入另一份不发送的草稿。往返切换，确认草稿、群组、任务分别属于正确账号。聚合聊天里的发送身份固定为该会话所属账号。
4. 需要测试监听时，只选择本人可控、参与者同意的测试群，模式选“仅预览”，保存配置后再启动。由同意测试的参与者发一条**启动后的新消息**，查看候选与“未修改联系人”的结果，然后停止该账号监听。
5. 确认身份、范围和预览符合预期后，才按需在受控对象上测试少量真实发送、添加或邀请。真实动作提交后若显示“未核实”，先检查实际结果，不要连续重试。
6. 最后停止两号监听并安全退出，再按下一节重新打开，检查有效会话是否恢复、监听是否仍停止。

自动测试通过不等于实际 Telegram 写入已验证。媒体权限、邀请资格、平台限制和保存号码导出能力，都需要在自己的可控场景确认。

## 8. 找到需要的功能

左侧有七个页面：[README 的功能速查表](../README.md)可以随时查阅。几个容易找错的入口是：

- **批量邀请**：在“联系人”页内切换标签；先确认账号、对象、目标群及本次邀请同意，再看执行前预览。
- **联系人清理**：也在“联系人”页内。“删除选中”先预览；“全部清空”需核对完整范围、备份和最终确认。范围未知时会阻止最终删除，备份没有一键恢复。
- **AI 回复**：从“聊天”的“资料与 AI”辅助区使用；**AI 任务草稿**从“任务中心”创建。AI 默认关闭，在“设置”配置服务后，还需逐次同意数据范围。草稿需要人工审阅，发送或执行仍由你确认。

## 9. 以后重新打开、暂停和安全退出

### 重新打开

打开终端，按第 3 节进入**同一个包含 `server.py` 的目录**，再运行：

```sh
source .venv/bin/activate
export TG_WORKBENCH_STATE_DIR="$HOME/.local/share/telegram-workbench"
python server.py
```

这组命令也适用于误关网页后重新打开。若相同数据目录的后台仍在运行，命令会打开现有面板，不会另建一套账号数据；第二个终端随后返回提示符是正常现象。若后台已经退出，则会重新启动。不要使用旧书签或手工拼接地址。

### 暂停自动化

顶部“暂停全部自动化”用于暂停新的自动化写入；已提交请求仍可能完成，人工聊天仍可使用。只处理一个账号时，在该账号的“监听”页选择暂停或停止。停止不会撤销已经添加的联系人。

恢复前先核对账号、网络、权限、平台等待与任务结果。“恢复全局自动化”可能恢复符合条件的原监听；邀请需检查后恢复，清空需重新准备与完整确认。解除本地暂停不代表平台限制已经解除。

### 安全退出

在“设置 → 退出后台程序”查看受影响的工作，再确认退出，等待原启动终端返回命令提示符后再关终端。

**关闭网页或锁定面板都不会停止后台。** 正常退出优先使用设置中的退出流程；异常中断后重开时，先检查“未核实”项，不要把它们当作失败重复提交。电脑需要保持唤醒与联网，关机和休眠期间不能保证运行。

## 10. 保存本机数据

指定的数据目录中，`workbench.sqlite3` 保存应用数据，`accounts/<内部账号ID>/account.session` 保存账号会话。会话相当于登录授权，不是可公开分享的普通配置文件。

数据目录应仅由你的当前用户访问：程序将私有目录权限设为 `700`、私有文件设为 `600`。不要在运行中搬动或手动编辑数据库与会话，不要用放宽到所有人可写的权限解决问题。

“设置”中的应用备份可能包含会话和服务密钥，联系人清空备份也可能包含个人信息；都只应保存在可信本机，不要附到 GitHub。遇到问题，按[常见问题中的报告说明](troubleshooting.md)提供脱敏信息。
